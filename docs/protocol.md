# 厂商 NVMe 命令协议与 mnv_cli 分析

来源：对 `mnv_cli`（CLI 版本 1.0.20.1040，x86-64，带符号表）的反汇编，以及用 gdb 截获它发出的每条 `NVME_IOCTL_ADMIN_CMD`。原始抓包在 [traces/](traces/)，抓包方法见 [tools/README.md](tools/README.md)。卡的固件版本 1.0.27.1043。

除非另外说明，下面的内容都是**已验证**的：抓包里出现过，并且 `an1500ctl.py` 按这些格式和卡通信成功。

## 1. mnv_cli 的显示错误

| 现象 | 原因 | 位置 |
|---|---|---|
| JBOD 卷在 `info -o vd` 里显示为 "RAID0" | `RaidModeStr()` 把模式值 0x0F 映射到字符串 "RAID0"（其他未知值才是 "unknown"） | `0x439bef`，判断在 `0x439c49` |
| `Supported RAID Mode` 从不显示 JBOD | `Adapter_PrintInfo()` 只判断 0x01/0x02/0x08/0x10/0x20/0x40/0x80 这几位，0x04 没有对应文字 | `0x404ca7`，判断从 `0x40533d` 开始 |

- 创建命令里 0x0F 确实代表 JBOD：`chooseRaidMode()`（`0x439a87`）把参数 `JBOD` 转成 0x0F，`RaidModeStrInCreate()`（`0x401d77`）把 0x0F 显示成 "JBOD"。
- `mnv_cli create` 的帮助只列了 `-r <0|1|10>`，但实际接受 `-r JBOD`。
- `mnv_cli create -r 0 -d <单个盘>` 发出的模式值也是 0x0F：厂商工具把单盘 RAID0 当作 JBOD。
- 不依赖新工具、直接看原始模式值的方法：`sudo gdb -q -batch -x docs/tools/mnv.gdb --args ./mnv_cli/mnv_cli info -o vd`，输出里的 `RAIDMODE_RAW=0xf` 就是 JBOD。

**推断**：支持模式字里的 0x04 位代表 JBOD。依据是 mnv_cli 认识的八种模式里只有 JBOD 没有对应的位，而且这张卡（该字为 0x0007）接受 JBOD 创建。没有在固件里找到直接证据。

## 2. 两种命令通道

所有命令都是 NVMe admin 命令，发给 `/dev/nvme0`，`nsid=0`，数据长度 4096。

### 2.1 简单读命令：操作码 0xE2

- `CDW12` = 子命令，`CDW14` = 对象编号，其余为 0；数据方向是卡到主机。
- 回复：`"MNV "`（4 字节）+ 状态 u32（0 = 成功）+ 内容（从偏移 8 开始）。下文的结构体偏移都相对于"内容"。

| CDW12 | 含义 | CDW14 |
|---|---|---|
| 0xE0 | 控制器信息 | 0 |
| 0xE1 | 物理盘信息 | PD 编号 |
| 0xE2 | 卷信息 | VD 编号 |
| 0x2E3 | 卷的后台任务状态 | VD 编号 |
| 0xE5 | 命名空间列表 | 0 |
| 0x3E0 | 设置时间（mnv_cli 每次启动都发，无数据） | 见下 |

- 设置时间：`CDW13 = (unix时间 >> 16) << 16`，`CDW14 = unix时间 & 0xFFFF`（抓到 `0x6afd0000` / `0x513f`，对应 1794986303）。an1500ctl 不发这条命令。
- 状态码：查询不存在的 PD 返回 6；查询不存在的 VD 返回非 0（具体值没有记录）。

### 2.2 请求/应答命令对：0xCB 然后 0xCE

mnv_cli 的 `create`、`delete` 走这个通道（`PairCMDDevice_sendCommand`）。两条命令都带 `CDW10 = 0x400`、`CDW15 = 0x564E4D`（"MNV"）。

1. `0xCB`（主机到卡）发送请求缓冲区：

   | 偏移 | 长度 | 内容 |
   |---|---|---|
   | 0x00 | 4 | `"MNV\0"` |
   | 0x04 | 2 | 0x1002 |
   | 0x06 | 2 | 负载长度 |
   | 0x08 | 2 | 请求码（卷操作为 0xE2） |
   | 0x0A | 2 | 动作（0 = 查询，3 = 创建，4 = 删除） |
   | 0x0C | 4 | 0 |
   | 0x10 | - | 负载 |

2. `0xCE`（卡到主机）取回应答：`"MNV "` + 状态 u32 + 内容。

状态码：0 成功；查询不存在的 VD 返回 7。

#### 创建卷：请求码 0xE2，动作 3，负载 0x270 字节

| 偏移 | 类型 | 内容 |
|---|---|---|
| 0x00 | u8 | RAID 模式：0x00 RAID0，0x01 RAID1，0x0F JBOD |
| 0x01 | u8 | 物理盘个数 |
| 0x04 | u16 | 条带大小，单位扇区：0x100 = 128K，0x200 = 256K，0x400 = 512K（JBOD 也填 0x100） |
| 0x08 | u32 | 初始化方式：0 = quick（清前 64KB），3 = none |
| 0x0C | u16[] | 物理盘编号，没用到的项填 0 |
| 0x4C | char[] | 卷名，最多 16 个字符，只能是字母、数字、空格、下划线；默认 `VD_<编号>` |
| 0x68 | u8 | 1 = 只查询结果容量，不创建；0 = 真正创建 |

- mnv_cli 先发一次查询（0x68 = 1，`MNV_VD_QuerySize`），再发一次创建（0x68 = 0，`MNV_VD_Create`）。
- 查询的应答内容：偏移 4 是扇区大小 u32，偏移 8 是扇区数 u64。
- 创建后内核自动出现新的块设备，不需要手动重新扫描。

#### 删除卷：请求码 0xE2，动作 4，负载 8 字节

- `u16 VD 编号`、`u8 0`，后 5 个字节 mnv_cli 没有初始化；抓到的实际值是 `00 02 00 00 00`。
- an1500ctl 原样发送这组字节（卡接受过的请求）。**未验证**后 5 个字节填 0 是否也可以。
- 删除后内核自动移除块设备。删除前 mnv_cli 只做了若干查询，没有发命名空间 detach 命令。

### 2.3 没用到的第三种写法（仅来自反汇编，未验证）

`doSCreate`（`0x41c00f`）和 `doSDelete`（`0x41c5e9`）用操作码 0xE2 直接写：

- 创建：`CDW12 = 0xE2 | 0x03<<8 | 条带(0/1/2)<<16 | 模式<<24`，`CDW13` = 物理盘位图，`CDW14` = 命名空间个数。
- 删除：`CDW12 = 0xE2 | 0x04<<8 | VD编号<<16`。

抓包里从没出现过，没有在卡上试过。

## 3. 结构体（偏移相对于应答内容，即应答缓冲区偏移 8 之后）

### 3.1 控制器信息（0xE0）

| 偏移 | 类型 | 内容 | 这张卡的值 |
|---|---|---|---|
| 0x08 | u16×4 | 固件版本四段 | 1.0.27.1043 |
| 0x10 | u16×4 | VID、SVID、DID、SDID | 1b4b、1b96、2241、4000 |
| 0x18 | u8 | 修订号：0x10 位 = "A"，0x20 位 = "B"，低 4 位是数字 | 0x20 |
| 0x19 | u8 | 端口数 | 2 |
| 0x1A | u8 | 每个卷最多几块盘 | 2 |
| 0x1B | u8 | 最多几个卷 | 2 |
| 0x1C | u8 | 最多几块盘 | 2 |
| 0x1D | u8 | 每个卷最多几个命名空间 | 1 |
| 0x1E | u8 | 最多几个命名空间 | 4 |
| 0x2A | u16 | 支持的模式：0x01 RAID0，0x02 RAID1，0x04 JBOD（推断），0x08 RAID10，0x10 RAID5，0x20 RAID50，0x40 RAID6，0x80 RAID60 | 0x0007 |
| 0x2C | u8 | 缓存：0 关，1 开 | 1 |
| 0x2D | u8 | 支持的后台任务：0x01 初始化，0x02 重建，0x04 同步，0x08 迁移，0x10 巡检 | 0x13 |
| 0x2E | u8 | 支持的条带：0x01 128K，0x02 256K，0x04 512K | 0x07 |
| 0x2F | u8 | 修订号后缀：0 "V"，1 "D"，2 "B"，3 "A" | 2（显示为 B0B） |
| 0x30 | u32 | 功能：0x02 Import，0x04 RAID（没有则是 JBOF），0x08 Namespace，0x10 Dump，0x20 NMIC | 0x1E |
| 0x38 | char[20] | 序列号 | WUBT22230375 |
| 0x50 | 4 字节一项 | PCIe 链路：类型（1 = Root Complex，0 = End Point，0xFF = 结束）、编号、速率（3 = 8Gb/s）、宽度 | RC0 x4，RC1 x4，EP0 x8 |

### 3.2 物理盘信息（0xE1）

| 偏移 | 类型 | 内容 |
|---|---|---|
| 0x00 | u16 | PD 编号 |
| 0x02 | u8 | 标志：0x01 已分配，0x02 正在巡检，0x08 可导入，0x10 故障，0x20 SMART 严重警告 |
| 0x0C | char[40] | 型号 |
| 0x34 | char[20] | 序列号 |
| 0x48 | u32 | 扇区大小 |
| 0x4C | char[8] | 固件版本 |
| 0x58 | u64 | 扇区数 |
| 0x60 | u16 | 后端 RC/插槽编号 |
| 0x62 | u16 | 后端命名空间编号 |

### 3.3 卷信息（0xE2）

| 偏移 | 类型 | 内容 |
|---|---|---|
| 0x00 | u16 | VD 编号 |
| 0x02 | u8 | 状态：0 Functional，1 Degrade，2 Deleted，3 Missing，4 Offline，5 Partially Optimal，6 Foreign，7 Importable，8 Not Importable，9 Initialization，10 Rebuilding，11 Error Handling |
| 0x03 | u8 | 1 = 可导入 |
| 0x04 | u8 | **RAID 模式**（0x0F = JBOD） |
| 0x05 | u8 | 物理盘个数 |
| 0x08 | u64 | 扇区数 |
| 0x10 | u16[] | 物理盘编号，0xFFFF = 空 |
| 0x51 | u8 | 校验盘个数（RAID6/60 才有意义） |
| 0x52 | u16 | 条带大小，单位扇区 |
| 0x54 | u32 | 扇区大小 |
| 0x58 | char[16] | 卷名 |

### 3.4 后台任务状态（0x2E3）

| 偏移 | 内容 |
|---|---|
| 0x01 | 任务：1、2 初始化，3 重建，4 同步，5 迁移，7 巡检 |
| 0x03 | 进度百分比 |
| 0x04 | 1 = 运行中，2 = 暂停，其他 = 没有任务 |

只观察到"没有任务"的情况，其他取值来自反汇编（`VD_PrintBGAStatus`，`0x406335`）。

### 3.5 命名空间列表（0xE5）

每项 0x60 字节，共"最多命名空间数"项；偏移 4 为 0 的项是空的。

| 偏移 | 类型 | 内容 |
|---|---|---|
| 0x00 | u8 | 命名空间编号（对应 `/sys/block/nvme0nX/nsid`） |
| 0x01 | u8 | 父对象类型：1 = VD，0 = PD |
| 0x02 | u16 | 父对象编号 |
| 0x04 | u8 | 标志：0x01 有效，0x04 活动 |
| 0x05 | u8 | 卷状态：1 或 10 显示为 Unhealthy，其他为 Healthy |
| 0x08 | u32 | 扇区大小 |
| 0x10 | u64 | 扇区数 |

## 4. 实测到的容量

| 配置 | 扇区数 | 说明 |
|---|---|---|
| 单块物理盘 | 2000409264 | - |

## 5. mnv_cli 的命令分发

- `info`、`ns` 走 `doSInfo` / `doSNS`，用 0xE2 简单读命令。
- `create`、`delete` 走 `doCreate`（`0x40206f`）/ `doDelete`，用 0xCB/0xCE 命令对；过程中的查询也用命令对（请求码 0xE0/0xE1/0xE2、动作 0，以及 0xE3、动作 2）。
- 其他相关函数：`LD_PrintInfo` `0x405d3d`，`HD_PrintInfo` `0x4041ee`，`NS_PrintInfo` `0x406a27`，`MNV_VD_Create` `0x43cb09`，`MNV_VD_Delete` `0x43cd76`，`MNV_Adapter_PassthruAdmin` `0x43b719`，`getAdapterInfoSA` `0x411734`。
- `mnv_cli oemdata -v <SVID> -d <SDID> -s <序列号> -m <型号>` 可以改写 OEM 数据（见 [flash-layout.md](flash-layout.md)）。**没有执行过。**
